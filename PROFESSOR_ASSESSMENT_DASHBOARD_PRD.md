# Professor In-Chat Assessment Dashboard - PRD

## Executive Summary

This PRD outlines the design and functionality for a professor-facing dashboard that visualizes student performance on in-chat assessments. The dashboard provides insights into how students are performing across different learning nodes and assessments within a class.

## Context & Background

### What are In-Chat Assessments?
In-chat assessments are interactive quizzes generated by an AI tutor during student conversations. When a student is learning a topic (node), the AI tutor can automatically generate assessment questions to evaluate understanding. These assessments:

- Are created dynamically during conversations
- Use Formedible forms (text, textarea, select, radio, multiselect, number, checkbox)
- Are automatically scored based on correct answers
- Generate AI feedback for students
- Are linked to specific learning nodes (PathwayNode) within a class

### Current Data Structure

The system stores assessment data in MongoDB with the following structure:

**InChatAssessment** (Assessment Template):
- `id`: Unique identifier
- `topic`: Assessment topic (e.g., "Supervised vs. Unsupervised Learning")
- `nodeId`: Links to PathwayNode (learning node)
- `nodeTitle`: Title of the learning node
- `fields`: JSON array of form fields with question labels
- `correctAnswers`: JSON object with correct answers
- `createdAt`: When assessment was created

**InChatAssessmentResponse** (Student Submission):
- `id`: Unique identifier
- `assessmentId`: Links to InChatAssessment
- `studentId`: Links to User (student)
- `responses`: JSON object with **question labels as keys** and student answers as values
  - Example: `{ "What is supervised learning?": "labeled_data", "What is regression?": "continuous" }`
- `score`: Float (0-100) - calculated percentage
- `feedback`: String - AI-generated feedback
- `submittedAt`: Timestamp

**Related Models**:
- `User`: Students and professors
- `Class`: Course/class entity
- `PathwayNode`: Learning nodes within a pathway
- `LearningPathway`: Collection of nodes for a student in a class

## User Stories

### As a Professor, I want to:

1. **View aggregate performance** - See overall assessment scores for each student across all assessments
2. **Understand student progress** - See which nodes students have completed assessments for
3. **Review individual assessments** - See specific questions asked, student answers, and scores
4. **Identify struggling students** - Quickly spot students with low aggregate scores
5. **Track node coverage** - See which learning nodes have assessments and which don't
6. **Review AI feedback** - See what feedback was given to students

## Dashboard Structure

### Page Layout: `/class/[classId]/assessments` or `/professor/assessments/[classId]`

The dashboard is organized hierarchically: **Class → Students → Nodes → Assessments**

## Data Aggregation Logic

### Aggregate Score Calculation

For each student in a class:

```javascript
// Pseudocode
const studentResponses = getAllResponsesForStudent(studentId, classId);
const scores = studentResponses.map(r => r.score).filter(s => s !== null);
const aggregateScore = scores.length > 0 
  ? scores.reduce((sum, score) => sum + score, 0) / scores.length 
  : null;
```

### Performance Notes Generation

Generate 1-2 sentence summary based on:

1. **Overall Score**: "Excellent performance" (>85%), "Good performance" (70-85%), "Needs improvement" (<70%)
2. **Trend Analysis**: Compare recent scores vs older scores
3. **Node Performance**: Identify strongest and weakest nodes
4. **Consistency**: High variance = "inconsistent performance", low variance = "consistent performance"

Example algorithm:
- If aggregateScore > 85: "Excellent overall performance"
- If aggregateScore < 70: "Overall performance needs improvement"
- Find node with highest average score: "Strongest in [Node Title]"
- Find node with lowest average score: "Consider reviewing [Node Title]"

## Technical Implementation Notes

### Data Queries Required

1. **Get all students in class**:
   ```prisma
   ClassEnrollment.where({ classId }).include({ student: true })
   ```

2. **Get all assessment responses for a student in a class**:
   ```prisma
   InChatAssessmentResponse.where({ 
     studentId,
     assessment: { node: { pathway: { classId } } }
   }).include({ 
     assessment: { include: { node: true } }
   })
   ```

3. **Group responses by node**:
   - Group `InChatAssessmentResponse` by `assessment.nodeId`
   - For each node, group by `assessmentId`

4. **Calculate aggregates**:
   - Average score per student
   - Average score per node
   - Count of assessments per student/node

### API Endpoints Needed

- `GET /api/professor/assessments/[classId]` - Get all assessment data for a class
- `GET /api/professor/assessments/[classId]/student/[studentId]` - Get detailed student view
- `GET /api/professor/assessments/[classId]/aggregates` - Get aggregate statistics

### Data Format for Frontend

```typescript
interface StudentAssessmentData {
  studentId: string;
  studentName: string;
  studentEmail: string;
  aggregateScore: number | null; // Average of all scores
  assessmentCount: number;
  performanceNotes: string; // AI-generated summary
  nodes: NodeAssessmentData[];
}

interface NodeAssessmentData {
  nodeId: string;
  nodeTitle: string;
  nodeDescription: string;
  assessments: AssessmentDetail[];
}

interface AssessmentDetail {
  assessmentId: string;
  topic: string;
  submittedAt: Date;
  score: number | null;
  questions: QuestionAnswer[];
  feedback: string | null;
}

interface QuestionAnswer {
  question: string; // The question label
  studentAnswer: string | number | boolean | string[];
  correctAnswer: string | number | boolean | string[];
  isCorrect: boolean;
}
```

## Notes for Implementation

1. **Performance Notes**: These can be generated on-demand or cached. Consider generating them when viewing the dashboard for the first time.

2. **Empty States**: Handle cases where:
   - Student has no assessments yet
   - Node has no assessments
   - Class has no students

3. **Permissions**: Ensure only professors teaching the class can access this dashboard.

4. **Real-time Updates**: Consider WebSocket updates if assessments are being completed in real-time during class.

5. **Data Privacy**: Ensure student data is only visible to authorized professors.

## Conclusion

The hierarchical structure (Class → Students → Nodes → Assessments) allows for both high-level overview and detailed drill-down capabilities.
