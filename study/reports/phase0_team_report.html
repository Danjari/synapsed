SynapsEd Phase 0 Validation

Team report · Generated July 01, 2026 at 11:59

What is this?

Before we test SynapsEd with real students, we run a synthetic validation: 50 computer-generated student profiles (different majors — CS, Business, Health, Humanities, etc.) each get a personalized course pathway. We then check whether the paths are meaningfully different based on each student's survey — not just different lesson titles on the same route.

An independent AI reviewer (Anthropic Claude) scores each path. The course paths themselves are built by a separate model (Google Gemini). We only move to human studies when every quality gate passes — we do not lower the bar to force a pass.

Run 1 (first attempt) Run 3 (final)

What went wrong in Run 1

  • AI judge barely missed — 3.46/5 (needed 3.5). Some paths looked cosmetic.
  • Learning-style leak — 2 of 6 control pairs failed (nursing, math).
  • Technical issues — retired Claude model, Gemini skipping structured output, rate limits (all fixed).

What we changed

Run 2 — stronger generator instructions (prompt v2.0)

  • Learning style may only change lesson wording, never which syllabus sections appear.
  • Ethics/health students: 4+ ethics sections. Prompting-focused: 3+ prompting sections.
  • Anti-cosmetic rule + self-check for section-count differences.

Run 2 result: judge improved to 4.0 ✅ but learning-style test got worse (50%) ❌

Run 3 — structure lock for learning-style control students

  • For the 6 "twin" students (same survey except learning style), we now copy the exact syllabus structure from their matched partner and only rewrite descriptions.
  • This enforces our experimental design: learning style is not allowed to reroute the course.
