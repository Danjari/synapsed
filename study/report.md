# Phase 0 Synthetic Validation — Team Report

**Branch:** `study`  
**Last updated:** June 2025  
**Audience:** SynapsEd research team

---

## 1. What we are doing

Before human studies, we must show that SynapsEd’s pathway generator **structurally personalizes** learning paths — not just rephrases titles while giving everyone the same syllabus tour.

**Phase 0** is an offline synthetic validation gate:

```
syllabus (7 blocks) → 50 cross-field student profiles → generate pathways → evaluate → PASS/FAIL
```

If Phase 0 fails, we improve the prompt or generator. We do **not** proceed to human subjects until it passes on merit.

---

## 2. Research integrity

**We do not relax thresholds to force a pass.** That would be unethical and would undermine the paper.

| Principle | Implementation |
|-----------|----------------|
| Pre-registered hypotheses | H1–H5 defined in `pathway_generation_spec.json` before viewing results |
| Fixed gate thresholds | `study_config.yaml` — changed only with team agreement and documentation |
| Independent judge | **Anthropic Claude** evaluates pathways generated by **Google Gemini** |
| Honest judge prompt | Rubric instructs Claude to penalize cosmetic personalization and not inflate scores |
| Failure is informative | Exit code 2 means fix the system, not the metrics |

---

## 3. Why 50 cross-field profiles

Ten personas were enough to prototype. **Fifty students from different fields** taking the same AI literacy course gives us:

- **Realism** — CS, Business, Economics, Math/Stats, Health, Humanities students with field-appropriate survey answers
- **Statistical power** — hundreds of within/between-cluster pairs
- **Anti-chance argument** — similar profiles → similar block coverage; contrasting fields → divergent coverage
- **Style controls** — pairs that differ only in `learning_1` test that learning style does not reroute structure

Regenerate profiles:

```bash
python scripts/05_generate_synthetic_profiles.py
```

## 4. Key structural decisions

### 4.1 Syllabus as 7 tagged blocks

Every generated node carries `syllabusBlockId`. This lets us measure **block coverage**, not cosmetic title differences.

| Block | Content |
|-------|---------|
| `block_01` | Classic AI basics |
| `block_02` | Generative AI core |
| `block_03`–`block_04` | Prompting basics → advanced |
| `block_05a` | Business & workplace track |
| `block_05b` | Projects & workflows (RAG, fine-tuning) |
| `block_06` | Ethics capstone (every pathway) |

**Why:** Title Jaccard alone was misleading — pathways shared ~70–80% structural spine with different wording.

### 4.2 Structural vs cosmetic personalization

The generation prompt requires varying **which blocks appear** and **node counts per block**.  
`learning_1` (learning style) must **not** change block selection — only description tone.

### 4.3 Independent LLM judge (Anthropic Claude)

| Component | Model | Role |
|-----------|-------|------|
| Pathway generator | Gemini (`GEMINI_MODEL`) | Creates pathways from survey + syllabus |
| Judge | Claude (`CLAUDE_JUDGE_MODEL`) | Scores alignment on 5-dimension rubric (1–5) |

This separation reduces same-model bias. Disclose both model IDs in the paper.

**Required env vars:**

```bash
GEMINI_API_KEY=...          # generation
ANTHROPIC_API_KEY=...       # judge
CLAUDE_JUDGE_MODEL=claude-sonnet-4-20250514
```

## 5. Evaluation layers (script 09)

| Layer | Metric | Gate (not laxable without team consent) |
|-------|--------|----------------------------------------|
| Block diversity | Mean multiset Jaccard across all pairs | **< 0.92** |
| Contrast hypotheses | H1–H5 pass rate | **≥ 80%** |
| Within-cluster consistency | Same cluster → similar coverage | mean **≥ 0.65** |
| Contrasting clusters | e.g. humanities vs CS | mean **≤ 0.70** |
| Style-control invariance | Paired profiles, sequence Jaccard | **≥ 80%** pairs pass 0.85 |
| Claude judge | Stratified sample (default 15) | mean **≥ 3.5** |
| Title Jaccard (secondary) | Script 08 | diagnostic only |
